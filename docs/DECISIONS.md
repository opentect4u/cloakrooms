# Decisions

Choices made where CLAUDE.md and the reference documents were silent or unclear.
Each one is the simplest option that works. Newest phase at the bottom.

| 2 | App identity | Package and application ID `com.synergic.cloakroom`, app name "Cloak Room". | Not specified. |

## Phase 2: login, roles and single session

| # | Topic | Decision | Why |
|---|---|---|---|
| 22 | New setting `PWD_MIN_LENGTH` | General tab, INT, default 8, allowed 4–32. Used for change password, add user and reset password. | A password rule is a business number, so it must live in `md_setting`. The seed passwords (`Admin@123`, `User@123`) are 9 and 8 characters long. |
| 23 | New setting rows on old databases | At every start the app adds any seed setting that is missing from `md_setting`. It never changes rows that already exist. | So a phone that already has data gets new settings like `PWD_MIN_LENGTH` without "Reset demo data". |
| 24 | User IDs | Saved and compared in lower case (`ADMIN` logs in as `admin`). New IDs: 3–20 characters, letters, digits, dot or underscore. | Avoids two users that differ only in capitals. |
| 25 | Login message for unknown user or wrong password | The same message for both: "Wrong user ID or password." A wrong password also says how many attempts are left. | Does not tell a stranger which user IDs exist. |
| 26 | Order of login checks | Blocked user → password → single session. A wrong password is counted before the "Already logged in" check. | The "Already logged in since…" message is only shown to someone who knows the password. |
| 27 | Blocking applies to admins too | `MAX_LOGIN_ATTEMPTS` blocks any user, including the admin. In debug builds, the Login screen's ⋮ menu has "Reset demo data" to recover. | CLAUDE.md does not exempt admins. With one admin and no server, a debug-only way back is needed for testing. |
| 28 | Unblock and reset password | Unblock sets `failed_attempts` to 0. Reset password sets `must_change_pwd = 'Y'` and `failed_attempts` to 0, and does not unblock. | Simplest clear behaviour; each button does one thing. |
| 29 | Admin limits on own account | An admin cannot block, force logout or change the type of their own account. | Prevents locking yourself out or leaving no admin. |
| 30 | Where the session is remembered | The logged-in `md_user.id` is kept in the app's private SharedPreferences. At start the app checks that `md_user.device_id` still equals this phone's Android ID and that the user is not blocked. Otherwise it shows Login with the reason. | Keeps the user logged in across restarts, and honours a Force Logout or block made by an admin. |
| 31 | Force logout on the same device | Force Logout clears `device_id` and `session_started_at`, so the user can log in again anywhere. With only one phone, the forced user is simply asked to log in again the next time the app starts. | Same rule the server will enforce later. |
| 32 | Settings writes in phase 2 | `SettingsRepository.updateSettings` (admin check, validation, `depends_on`, `td_setting_log`) was built now, so that "a normal user cannot write settings" can be tested. The screen comes in phase 3. Password values are hashed. The log shows `******` instead of a password or hash. An empty password field keeps the current password. | CLAUDE.md asks for that test in phase 2. |
| 33 | Admin-only screens | Normal users do not see the Users button. The Users route is also not registered for them, and every admin method in the repository throws `NotAuthorizedException`. | Permission checks in both places, as CLAUDE.md requires. |
| 34 | Home screen | Until the Dashboard in phase 7, login leads to a simple Home screen: name, role, "Logged in since", Users (admin), Change password, Logout. | Something to land on after login. |
| 35 | Users screen now | The full Admin → Users screen (add, edit name/type, block/unblock, reset password, Force Logout, who is logged in and since when) was built in phase 2. | Force logout and blocking are phase 2 features and need this screen. |

## Phase 4: bill calculation, validators and numbering

| # | Topic | Decision | Why |
|---|---|---|---|
| 43 | Minutes stored | Whole minutes between check-in and check-out; seconds are dropped (24 h 00 m 59 s counts as 24 h 00 m). A check-out time earlier than check-in (wrong device clock) counts as 0 minutes. | Matches how the operator reads the times on the receipt. |
| 44 | Penalty when `PENALTY_FLAG = N` | Any penalty above 0 is refused with "Penalty is not allowed." A negative penalty is always refused. | CLAUDE.md: penalty = 0 when the flag is off. Refusing makes a wrong entry visible. |
| 45 | `taxable_amt` when GST is off | Equals `net_amt` (base + penalty), with all tax amounts 0. | The whole amount is the value of the service; nothing is tax. |
| 46 | `taxable_amt` when the penalty has no GST | The taxable value of the GST base only (the rent). The penalty is collected on top, untaxed. So `net_amt = taxable + GST + penalty`. | The penalty is not part of the taxed supply when `PENALTY_GST_FLAG = N`. |
| 47 | Rounding | Every amount is rounded HALF_UP to 2 decimals at each step: base, taxable, GST, then CGST = round(GST ÷ 2) and SGST = GST − CGST. | CLAUDE.md; CGST and SGST always add up exactly. |
| 48 | Mobile number | 10 digits starting with 6, 7, 8 or 9. Spaces and a leading `+91` are removed. | Indian mobile numbers. |
| 49 | PNR | Optional when `PNR_REQUIRED = N`. When given: letters and digits only, up to 20 (the MySQL column is VARCHAR(20)); saved in capitals. | Keeps the value clean for search. |
| 50 | No ID proof | When `ID_PROOF_REQUIRED = N` and no ID is given, `id_proof_id = 0` and `id_number = ''`. A type without a number (or a number without a type) is still refused. | Both columns are NOT NULL in the schema. |
| 51 | ID masking | With `ID_MASK_FLAG = Y`, `id_number` is saved as `XXXX` + the last 4 characters (e.g. `XXXX9012`); the full number is never stored. Spaces and dashes are removed first. At least 4 characters are needed. | CLAUDE.md: store and print only the last 4 digits. The `XXXX` makes it clear on every report that the number is masked. |
| 52 | Daily bill limit with count 0 | `DAY_BILL_LIMIT_COUNT = 0` means no limit, even when the flag is on. | The seed table says "0 = no limit". |
| 53 | UPI reference | Kept only for UPI bills, trimmed, up to 50 characters. Choosing UPI while `UPI_ENABLED = N` is refused. | The MySQL column is VARCHAR(50). |
| 54 | Number series | `md_user_counter` holds one row per user, series (R/B) and period. The next number is reserved inside the same Room transaction as the insert, so a failed insert gives the number back and two counters can never get the same number. A test makes 20 numbers at the same moment and checks they are all different. | CLAUDE.md: "two numbers can never collide". |
| 55 | Numbers above 99,999 | The number gets a sixth digit (`U02-100000`). | Never stops a check-in. |

## Login shift (td_assign_shift)

| # | Topic | Decision | Why |
|---|---|---|---|
